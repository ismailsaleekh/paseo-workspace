## Boundary regressions and verification status

- `service.test.ts`: actual Pi/private-socket/owned-WebSocket wiring; real app presentation/action and genuine document-error recovery; deterministic display deadline expiry with late-receipt refusal and prior-version retention; conflicting display ownership; invalid remote action schemas and oversized observations before mutation.
- `attachment.test.ts`: actual Pi get-state verification during an in-flight tool/context request; malformed, over-depth, over-byte-limit and pre-attachment frames disconnect without invoking the host; revoked runtime/session generations and cancellation.
- `storage.test.ts`: actual immutable-file write failure preserves the old source/state across reopen; concurrent state CAS and state changes during staged source replacement; corrupt persisted records remain loud failures.
- `controller.test.ts`: action JSON and nonempty restoration snapshots traverse the actual generated inbound validator; decoding rejects malformed/deep/UTF-8-oversized JSON; reference stability is measured after wire decoding; retained-surface release/reopen rejects old-lifetime messages.

The independent connected browser loop and the owned real-browser document-error recovery passed in the candidate run recorded before these final boundary additions. That run still failed an owned controller test that compared a decoded object to its pre-serialization reference. The corrected test keeps the reference-stability assertion across local updates and separately checks decoded contents. All final additions/corrections must pass the default QA, scoped format/lint and independent judge before submission. No unexecuted test is claimed green.
