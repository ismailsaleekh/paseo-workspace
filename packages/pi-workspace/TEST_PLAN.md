## Required edge cases

- Inputs: empty/oversized/invalid UTF-8 source; conflicting or absent sources; symlink/directory/missing file; invalid revision; non-JSON/deep/oversized state; unknown action and remote action schemas; invalid/oversized client identifier; client forbidden on all other tools.
- Ownership: wrong runtime/session/source; two hosts on one authenticated connection; released/replaced bindings; malformed/duplicate/late receipts; old controller lifetime; hidden addressed client; unknown client; no display versus an existing unsupported display.
- State: source CAS, concurrent state CAS, state change during source replacement, failed restore preserving previous source/state, normal user text unchanged, no model request on local interaction, no publication manufactured by restoration.
- Capture: wrong operation, source/state revision or display identity; target invalidation before delivery and after decoding; timeout, abort and late callbacks; empty, malformed or oversized image; restored throttling and released capture debugger; no image on errors; no cached image, fallback client or backend renderer.
- Lifecycle: late join without re-present; a late joiner's mount receipt never reclaims the active role from a display touched in the meantime; navigation or renderer loss of a host window releases its guests; close/unmount/reconnect; source replacement with fresh document identity; termination remains visible as unresponsive; reopen clears it only through a new document; app composer survives.
- Policy: permission check and request both denied, device/display-media denial, navigation/window/download refusal, guest-only proxy and WebRTC policy. The real Electron oracle covers 26 in-document egress vectors, including nested-realm WebRTC, plus navigation/window/download attempts. Unit policy ports verify installation, not physical network containment.

## Evidence boundaries

The capture-port tests use controlled CDP replies to prove bindings and cleanup. A real-Electron regression also calls the production capture helper on a displayed WebContentsView before and after resizing and while another window covers its host, comparing its PNG pixels with the guest page and retaining diagnostic images. The immutable real Electron motif oracle remains the connected Pi-to-display pixel witness; controlled adapters cannot replace it. Likewise service/controller ports prove deterministic stale-base rejection, which the outside observer cannot reliably schedule, while the real oracle proves convergence.

A1 changes exactly two existing service expectations: accept multiple displays while retaining released/replaced refusal; use `CLIENT_UNAVAILABLE` for no-display screenshots while retaining recovery/listing/no-fabricated-image checks. Other existing tests and every judge file remain protected.

Plain web and the iOS adapter do not claim actual capture. No TUI/PTY suite is applicable because the package has no terminal UI or shortcuts. The Android companion's policy, deadline and capture are Kotlin code without JVM unit tests (the offline judge runs no Gradle tests); the emulator Root is their witness, and physical HyperOS 3 / Android 16 evidence is still required. Emulator results never replace it. DNS-only side channels are not observable with loopback sinks; on Android the companion's missing INTERNET permission denies sockets at the kernel, on desktop guest proxy enforcement is required.

No unexecuted check is green by virtue of appearing in this file. Record actual test, Root and certificate receipts separately.
